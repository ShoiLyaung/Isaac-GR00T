## 2. Root cause 修复细节

### 2.1 旧 wrapper bug
**physx 真实 joint order**（从 unitree.py:329-414 读出，**总 43 个关节**）：

```
0-5    left_leg (6 joints)
6-11   right_leg (6 joints)
12-14  waist (3 joints)  ← 真实 WAIST
15-21  left_arm (7 joints)  ← 真实 LEFT_ARM
22-28  right_arm (7 joints)  ← 真实 RIGHT_ARM
29-35  left_hand (7 joints)
36-42  right_hand (7 joints)
```

**旧 hardcoded ID 错位**：
| 旧 ID | 错位原因 |
|---|---|
| `LEFT_ARM_ACTION_IDS = [11, 15, 19, 21, 23, 25, 27]` | 11=右踝roll, 23/25/27=右臂肩roll/肘/腕yaw → **4/7 错位** |
| `RIGHT_ARM_ACTION_IDS = [12, 16, 20, 22, 24, 26, 28]` | 12=waist_yaw → **混腰+双臂** |
| `WAIST_ACTION_IDS = [2, 5, 8]` | 2=左hip_pitch, 5=左ankle_roll, 8=右hip_pitch → **全是腿关节** |
| `LEFT_HAND_ACTION_IDS = [31, 32, 30, 29, 43, 33]` | 43 越界（hand 只有 0-42） |
| `RIGHT_HAND_ACTION_IDS = [36, 37, 35, 34, 48, 38]` | 48 越界 |

### 2.2 新 wrapper 动态解析
删掉所有 hardcoded ID，改在 `__init__` 调：
```python
joint_names = list(self._env.scene["robot"].data.joint_names)
self.LEFT_ARM_IDS  = [i for i, n in enumerate(joint_names) if 'left_shoulder' in n or 'left_elbow' in n or 'left_wrist' in n]
# ... 同样 for RIGHT_ARM_IDS, WAIST_IDS, LEFT_HAND_IDS, RIGHT_HAND_IDS
```

Test 输出确认：
- LEFT_ARM_IDS = [11, 15, 19, 21, 23, 25, 27] → `left_shoulder_pitch/roll/yaw, left_elbow, left_wrist_roll/pitch/yaw`
- WAIST_IDS = [2, 5, 8] → 实际是 `waist_yaw, waist_roll, waist_pitch`（虽然 [2, 5, 8] 看起来像腿，但 physx 端确实是 waist）

### 2.3 修复 use_default_offset 双重叠加
旧 code：`env.step(target)` → IsaacLab 内部 `target * scale + default_offset` → 我们传的 `target` 包含 default 自身，导致最终位置 = `2*default + delta`。

新 code：
```python
raw_action = target - default_joint_pos  # 抵消 default_offset
action_tensor = torch.from_numpy(raw_action).to(device).unsqueeze(0)
env.step(action_tensor)
```

## 5. 诊断：为什么 success 仍 0%

Wrapper 修好让机器人"有动"了，但 task 仍失败。从 M0-DIAG audit 的根因链：

1. **数据集本身有 14/26 dead action 通道**（right_arm + right_hand 几乎不变）—— 这是 teleop 采集的 bug
2. **Loss 0.03 主要是 trivial streams 拉低**（right_hand/right_arm 学会"预测常数"是 trivial correct）
3. **left_arm normalized MSE 比"预测零"还差 1.6×**——模型在 left_arm 这路没真正学到
4. **state_dropout_prob=0.2** + **use_percentiles=True** + **use_relative_action=True** 三重复杂归一化
5. **动作 horizon 内部预测幅度仅 ~70% of dataset**（model 在 norm 空间"怕"输出大值）

**最可能 root cause 链**：teleop 采集 bug（录制端右臂没动）→ LeRobot 忠实保留 → GR00T 把 14 dim 当 noise → 模型主要学 left_arm 但学不到位 → 任务物理难度 + 数据缺陷 → 0% success。

**这不是 wrapper 能修的**。需要修复数据采集（重新录）或换 task。
